# Generated write paths

Part of the `audit-generated-code` skill. The measured rules for what Nino.Generator emits on the write side (region
lengths, keyed headers, the presence byte, the write body's methods, polymorphic dispatch), each with its evidence
and the attempts that lost. Read it before changing `BodyEmitter`'s write paths, `FormatterEmitter`'s top-level
writes or `DispatchEmitter`, or when a generated serializer got slower or larger. How the JIT inlines and folds
these paths is `optimize`, references/jit.md; how it devirtualizes is references/dispatch.md there.

How every bullet here was proven: the source and IL of the fixture's write body, its Arm64 Tier 1 or FullOpts listing
and the offline (cross-JIT) x64 listing, local paired timings on Apple M4 against identical-binary (A/A) controls
with the same Core DLL on both sides, steady allocation, and the wire and round-trip comparisons at offsets 0, 1
and 7 (UTF-16 and UTF-8 strings where the body has any). Local timings decide only between candidates; a published
claim still needs runner numbers (`benchmark`).

## Region lengths

- **Write the length up front when a region consists entirely of one raw member group, reserving the header and
  payload together**: raw stores cannot queue deferred bodies, so the writer does not need to open a region or patch
  its length. Keep the begin/end path for mixed bodies and collections. This removed 2,747 generated bytes from the
  unit test project and reduced the Arm64 `PaddedItem[]` element loop from 428 to 252 machine-code bytes.
- **Patch a region's length directly (`PatchLength`, no nested writer region) wherever nothing inside can defer a
  body**: direct UTF-16 and UTF-8 string writes, raw members, and members or collections whose resolved formatter has
  `OpensBodies == false` (a built-in `List<int>`, say). Keep custom formatters conservative, keep the one-reservation
  raw prefix and the fixed-region path for wholly raw bodies, and reserve the preceding raw members, key and length
  together as before.
  - A keyed string member: the `KeyedStruct` writer gained 19 source bytes and 7 IL bytes, but fell from 1,232 to
    1,092 Arm64 Tier 1 bytes and from 953 to 863 offline x64 bytes. Four local 1,000-item ASCII writes went from
    5.20–5.23 to 5.10–5.12 µs at zero steady allocation. All 54 wire and round-trip comparisons matched across both
    string encodings and offsets 0, 1 and 7.
  - The outer keyed body when it has no collection elements and every member is raw or a direct string: another 140
    Arm64 Tier 1 bytes and 90 offline x64 bytes, with 20 more source bytes and 5 more IL bytes. Four local 1,000-item
    ASCII writes went from about 5.10 to 4.75–4.77 µs at zero steady allocation. The 54 byte and round-trip checks
    included a UTF-8-only body with no raw prefix.
  - Version-tolerant bodies with only raw members and direct strings: source grew by 20 bytes and IL by 5, while
    Arm64 Tier 1 shrank from 868 to 728 bytes and offline x64 from 703 to 613. Four 16-item ASCII rounds improved
    against the paired baseline. The 1,000-item results overlapped A/A after longer warmup, at zero steady
    allocation. All 54 wire and round-trip checks passed, including a UTF-8-only body.
  - A version-tolerant collection's member region (its elements are written before the region opens): the
    `NamedList` fixture added three source bytes with unchanged 38-byte IL. Arm64 Tier 1 fell from 1,672 to 1,532
    bytes and offline x64 from 2,495 to 2,405. Four 1,000-item ASCII runs fell from 5.95–6.10 to 5.32–5.84 µs at zero
    steady allocation. All 27 wire and round-trip probes passed.
  - A keyed collection (its region includes the elements, so the collection formatter must also have
    `OpensBodies == false`): saved 140 Arm64 Tier 1 bytes and 90 offline x64 bytes. Four 1,000-item writes fell from
    6.77–6.93 to 6.13–6.33 µs at zero steady allocation. A keyed list containing a deep class chain still writes and
    reads its deferred elements.
  - A version-tolerant body with a built-in `List<int>` member: gained 20 source bytes and 5 IL bytes but saved 140
    Arm64 Tier 1 and 99 offline x64 bytes. Four 1,000-item writes went from 4.79–5.13 to 4.57–4.61 µs at zero steady
    allocation. The 54 wire and round-trip probes covered both keyed and version-tolerant bodies.
  - Individual keyed entries with a built-in `List<int>` member: 1,000 ASCII writes fell from 7.06–7.10 to
    6.04–6.16 µs across four same-Core rounds at zero allocation. The generated file gained 19 bytes and the body
    gained 7 IL bytes, while Arm64 Tier 1 fell from 1,940 to 1,800 bytes and offline x64 from 2,785 to 2,688. All 27
    wire and round-trip probes passed, including null and wide strings at unaligned offsets.
- **Pack a keyed member's constant key and byte length into one unaligned header store on write; keep symbolic
  lengths on the existing path.** The real unit test project emitted 2,329 fewer source bytes. For `KeyedStruct`, the
  x64 listing changed four header stores to two and the Arm64 listing stayed the same size.

## The presence byte

- **Select the top-level presence byte once and share its write; preserve the generated equality operator (the null
  test's existing semantics) and the local writer on both entries** (`7804d75f`). The 583-file replay saved 1,256
  source bytes in 37 formatters and changed only the presence blocks. The two `SimpleClass` entries saved 4 IL bytes
  each. The buffer and byref entries went from 1,068/1,016 to 1,012/932 Arm64 FullOpts bytes and from 945/1,053 to
  898/982 offline x64 bytes. The 16- and 257-character byref probes at offset zero took less time in four M4 pairs,
  with variable identical-binary controls. The buffer null case initially lost, then overlapped the baseline spread at
  both offsets with longer isolated warmup. Other buffer, cold and whole-generator timings varied. Wire bytes, 0 B
  steady allocation, model reuse and collection matched. The modern and netstandard2.1 targeted configurations
  passed.
  - Do not share one capacity check across the null and non-null branches of the top-level local-writer wrappers: an
    earlier variant that did reduced the `SimpleClass` listing on both architectures, but the same-process Arm64 A/B
    moved from about 47 ns to 49 ns.

## The write body's methods

- **Merge standalone class writes that have no local-writer twin into the instance method** (as the read body is,
  `read-paths.md`) (`8ca095f4`). The unit test project saved 37,716 source bytes across 252 files in each replay
  state. The string-holder write kept 22 IL bytes and lost an 8-byte forwarder. The body stayed at 1,208 B on Arm64
  and 818 B on x64 cross-JIT, and the caller stayed at 272 and 214 B. Four local rounds showed no meaningful write
  timing change, with identical wire bytes and zero steady allocation. All 577 models were reused on edits and both
  Roslyn suites passed.
- **Keep by-reference static write bodies for structs.** A by-value instance body removed 6,375 source bytes across
  41 files and saved the 9-byte forwarder, but grew the Arm64 FullOpts bodies from 356 to 688 B for `NamedItem` and
  from 508 to 840 B for `WideItem`. The x64 cross JIT printed the unchanged 160 B caller, but omitted the candidate
  bodies with GC-tracked struct arguments. At 127 `NamedItem` elements the M4 writer slowed about 5–13% across four
  rounds at both offsets; wide timings were closer. Wire bytes, allocation, model reuse and collection matched. The
  prototype passed 86 and 87 targeted tests on .NET 8 and 10, respectively, and was withdrawn.

## Polymorphic dispatch

- **Outline exact writes in wider subtype dispatches when the subtype body nests; keep flat and raw writes inline.**
  Outlining every non-raw case made the 1,000-element unmanaged tuple workload consistently slower. The nesting gate
  left that dispatch unchanged and the open-class tuple workload improved in four local Arm64 rounds. Its Tier 1
  dispatch shrank from 2,476 to 604 bytes, with eight separate 332-byte helpers: count those helpers and the caller
  separately. The benchmark emitted 2,160 more source bytes and all tested wire outputs matched, including short
  writes to unaligned offsets.
- **Keep exact runtime type comparisons adjacent (each reads `value.GetType()` in place) when a subtype can be derived
  from; keep the first comparison exact and use `is` only for later sealed targets**: the JIT loads the method table
  once for the chain, and the first load establishes non-nullness without an explicit branch. The benchmark dispatch saved 774 source bytes and the sampled IL went from 256 to 151
  bytes. The Arm64 entries grew by 4 and 8 bytes; the x64 cross listings shrank from 1,148 to 602 and from 1,068 to
  519 bytes. Thread CPU and wall time varied against the same-binary controls, so it is a size change. Wire bytes,
  including unaligned writes, and 0 B steady-state allocation matched.
  - Do not hoist `value.GetType()` to a shared local: it saved 496 source bytes and shrank the sampled dispatch IL
    from 256 to 223 bytes, but Arm64 Tier 1 already loaded the method table once in the original chain; the shared
    local materialized a runtime type object and grew the dispatch from 604 to 672 machine bytes. The non-generic
    1,000-item case was slower in all four local rounds.
  - Do not use a shared generic comparison helper: it saved only 136 source bytes and grew the non-generic dispatch
    from 2,984 to 3,064 Arm64 Tier 1 bytes and from 1,148 to 2,281 x64 cross-JIT bytes.
  - Do not use `is` for every sealed target: it saved 936 source bytes and kept the method-table comparison, but added
    an explicit null branch before the chain. The non-generic case was slower than its paired baseline in four local
    rounds. The wire bytes matched and both probes allocated 0 B.
