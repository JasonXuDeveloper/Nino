# Changing the wire format

The bytes are the contract between .NET, Unity, Go, Rust, TypeScript and every program that stored them. A change to
them is deliberate, complete in one landing, and called out.

## Before

- Ask whether the owner wants it: a wire-format change nobody asked for is the owner's decision.
- Compare candidate encodings by size and speed in every runtime (a decoder that is fast in .NET but branchy in Go or
  TypeScript is not a win), and keep the format canonical: one encoding per value, so readers can reject the rest.
- Never give a type whose size depends on the host an encoding: refuse it, in the analyzer and at run time, and
  document a fixed-size form instead (the owner's rule). No bytes of it read everywhere: a 32-byte draft encoding of
  `System.Numerics.Vector<T>` (16, 32 or 64 bytes, chosen by the CPU) made x64 data unreadable on Arm64 and in Unity,
  so it is refused (NINO029, `NotSupportedException`) and the fixed-lane form is in docs/pitfalls.md
  (`tests/Nino.UnitTests.Subset/VectorLanes.cs`). How to test each width is `platforms`'.

## Everything that changes with it

| Place | What |
|---|---|
| `docs/spec/wire-format.md` | the encoding, its examples (Appendix A), §9 for what readers must reject |
| `src/Nino.Core` | writer and reader, every fast path (`optimize`, `platforms`: x64 ISAs, Arm64, no SIMD, big-endian guards) |
| `src/Nino.Generator` | the emitters that inline the encoding (`audit-generated-code`) |
| `src/Nino.Unity/Packages/com.jasonxudeveloper.nino/Burst/NinoBurst*.cs` | the Burst kernels, and `Assets/Test/Runtime/Burst/BurstKernelTests.cs`' golden bytes |
| `tests/conformance/` | regenerate (`dotnet run --project tests/conformance/Nino.Conformance -c Release -- --out tests/conformance/corpus`), new valid and malicious cases for the new encoding's edges (`untrusted` cases where .NET checks only with `NinoSettings.Untrusted`), `corpusVersion` when the corpus layout or schema changes. A regenerated corpus that does not change proves nothing: check that a sample type reaches the changed layout (r104's canonical fields for Int128, `DateTimeOffset` and `nint` inside raw structs regenerated byte for byte, as no sample held one, until `bcl-raw-host` and `bcl-raw-offset`) |
| `runtimes/go`, `runtimes/rust`, `runtimes/typescript` | reader, writer, fast paths, their tests and fuzzers; each reads the new corpus |
| `src/Nino.Codegen/Templates` | the generated readers and writers; regenerate the committed output (`NINO_UPDATE_GENERATED=1 dotnet test tests/Nino.Codegen.Tests`) |
| `src/Nino.Codegen/Inspect` | `nino-gen inspect` reads every encoding with the reader checks of spec §9 (`Inspector.cs`, `Scalars.cs`): a new encoding or check goes there too; `InspectCommandTests` reads the whole corpus, and `NINO_UPDATE_GENERATED=1` rewrites its texts (`tests/Nino.Codegen.Tests/Inspect/*.txt`) |
| golden-bytes tests | `tests/Nino.UnitTests/Serialization/GoldenBytesTests.cs`, `tests/Nino.Fuzz/Golden`, Unity's, any test with expected hex; for raw layouts `src/Nino.Unity/Assets/Test/Runtime/BclFixtures.cs`, which `tests/Nino.RuntimeTests` links and Unity's `BclLayoutTests` read (rewrite with `dotnet Nino.RuntimeTests.dll --write-fixtures 2> src/Nino.Unity/Assets/Test/Runtime/BclFixtures.cs` on .NET 10 x64) |
| docs | byte examples in README, `docs/`, the runtimes' READMEs and the nino.docs pages, whose `<Bytes>` figures and byte playground nino.docs' `bun run check:bytes` checks against Appendix A and the corpus (`audit-docs`) |
| benchmarks | sizes shown in reports; the old-main baseline for the A/B (`benchmark`) |

A change to the layout text alone (`NinoTypeLayoutAttribute.ToString()`, no byte changes) is a contract change too
and reaches: the corpus's JSON (regenerate), nino-gen's committed Go and Rust output, the Go parser (`layout.go`,
`tagged_build.go`) and `internal/sample/layouts.go`, the Rust derive's checks, `tests/derive.rs` and
`tests/compile_fail/*.rs`, `tests/conformance/gen.py` (then regenerate `types.rs` and `rustfmt` it), the spec's §8
grammar and the Go README, and the layout baseline: `LayoutEntry.FromLayout` (src/Nino.Generator/Common/LayoutBaseline.cs)
splits the text into a baseline's fields, and every `NinoLayouts.cs` users committed compares against the old text, so
a reworded encoding reads as a change to every type that has it (`audit-analyzer`, the layout baseline). Round 128 renamed `header=NullFlag` to `Presence` and `typeId=` to `id=` there (the Rust compile-fail
`.stderr` files carry columns: `TRYBUILD=overwrite`); with 4.0 unreleased, only the new spelling is read.

Grep for the old bytes in every form (hex with and without spaces, C# byte arrays, Go and Rust literals) before
calling it done: the Unity golden bytes were missed once and turned CI red after the landing.

## Proof

- The conformance corpus verifies in .NET, Go, Rust and TypeScript; every runtime round-trips every valid case and
  rejects every malicious case and truncation.
- The fuzzers (`audit-security`) and the full unit test matrix (`verify`), Unity's run included.
- Runner A/B against the previous main in every runtime (`benchmark`): the new encoding must not cost speed.

## Commit

One landing for the whole change (a main where .NET and Go disagree is never pushed), with a `Wire-Format:` trailer
naming the bytes that change and for which types, and the version it ships in. The docs site's changelog gets a "Wire
Format" entry first in its release section.
