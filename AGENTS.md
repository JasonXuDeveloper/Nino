# Nino

Source-generated binary serializer for C#: .NET (netstandard2.0 to net10.0), Unity (IL2CPP, Burst) and HybridCLR,
with runtimes that read and write the same bytes in Go, Rust and TypeScript (generated by nino-gen). Published to
NuGet (`Nino`, `Nino.AspNetCore`, `Nino.Codegen.Tool`, ...), OpenUPM, crates.io, npm and as a Go module. Public API,
code comments, commits and docs are in English; the docs site is English and Chinese.

## Commands

```bash
export PATH=$HOME/.dotnet:$HOME/go/bin:$PATH DOTNET_ROOT=$HOME/.dotnet      # cloud sessions
dotnet build                                                               # the solution (Nino.slnx), 0 warnings
dotnet test tests/Nino.UnitTests                                           # the unit tests (CONTRIBUTING.md has the matrix)
QUICK=1 FILTER='*SimpleTest*' benchmarks/run.sh                            # benchmarks while developing (`benchmark` skill)
python3 benchmarks/asm.py compare origin/main                              # what a change did to the machine code
tools/agents.sh                                                            # refresh the indexes below (--check in CI)
```

The Go, Rust and TypeScript runtimes have their own commands (`runtimes/*/AGENTS.md`). The website is the separate
repository JasonXuDeveloper/Nino.Docs (https://nino.xgamedev.net; its own AGENTS.md).

**Instruction files.** `AGENTS.md` holds the instructions (the open standard Codex, Cursor, Copilot and other agents
read); each `CLAUDE.md` next to one is the single line `@AGENTS.md`, which makes Claude Code import it. Edit only
`AGENTS.md`. Before you read or change files in a directory listed below, read its `AGENTS.md` in full (file map and
local rules): Claude Code loads it when it reads a file there, other agents may not. The two tables are generated by
`tools/agents.sh` from each file's `> Read when:` line and each skill's description; run it after adding or changing
one (CI runs `tools/agents.sh --check`, which also checks that every file is in its directory's map).

                Nino.AspNetCore, Nino.Codegen (+ .Tool: nino-gen), Nino.Unity (the Unity project and package),
                Nino.UnityTypes; src/Nino is the meta package

## Workflows

Repeatable procedures live in `.claude/skills/<name>/SKILL.md`: Claude Code loads them as skills, `.agents/skills`
links to the same files for other agents, and anyone can follow them as checklists. A change is done when the
`feature` skill's checklist is; it lands through `verify`; a review of the codebase is an `audit` round.

### Keep what you learn

Skills are the project's memory: a fresh session knows only what AGENTS.md and the skills say, so anything worth
reusing is written down before the task ends, in the same series of commits as the work (a `docs(skills)` commit).

- **What counts**: a rule or convention the owner states or corrects ("never write slower", "numbers only from
  runners"); an optimization technique that measured faster, and one that measured slower (so nobody retries it
  blind); a trap that cost time (a qemu flag, a JIT behavior, a CI failure that slipped through); a check or command
  that proves something; a new place a change must reach (a test, a doc, a runtime).
- **Where it goes**: into the skill that owns that kind of work (an optimization technique, faster or slower, to
  `optimize`, how to measure to `benchmark`, a new place for wire changes to `wire-format`, a docs rule to `audit-docs`, a local fact
  about some files to that directory's `AGENTS.md`, a rule for every task here). Nothing fits: a new skill, with its
  row in the `audit` scopes.
- **How it is written**: one bullet, the rule first in the imperative, then why, then the evidence (the case, the
  numbers, the commit): "Mark every small helper a read path calls `AggressiveInlining` ... `NinoLanes.Paired` stayed a
  call per load: AVX2 writes took twice as long". Extend the bullet that already covers it rather than adding a second;
  a rule that turned out wrong is corrected or removed, not contradicted further down.
- **Tell the owner** in the report which skill gained what.

### Keep the skills consistent

- **A rule is stated in full once**, in the skill that owns it; other skills it affects carry a check phrased for
  their job and point to the owner. After changing a skill, read the skills it names and the ones that own
  neighboring files (the `audit` scopes table) and add the pointer where it is missing.
- **Put a rule where the work that needs it loads it.** A rule for every task goes here; a rule for one kind of work
  goes in its skill; a directory's `AGENTS.md` holds only its file map and rules local to its files; the public skill
  holds what users' agents need. Search before adding a rule: extend the existing one.
- **Descriptions decide when a skill runs**: what it does, `Use when ...`, and `Triggers:` with the paths it owns,
  the symptoms, and the owner's words in English and Chinese. A skill that did not run when it should have gets the
  missing trigger.
- **Split, never shrink.** A skill that has grown past one concern is split by concern (every line moves, the old
  skill keeps a pointer, `audit` gains the scope, `tools/agents.sh` the index).
- **Decide, then say.** Do what clearly fits the project's rules without asking; ask only what is the owner's to
  decide (a public API removal, a wire-format change nobody asked for, spending CI or license time).

## Principles (every change)

1. **Fast on every platform.** x64 (AVX-512, AVX2, SSSE3), Arm64, Arm32 and other 32-bit targets, WebAssembly and no
   SIMD, Mono and Unity (IL2CPP), .NET Framework. A fast path is behind `#if` or a startup check with the shared path as
   fallback, and both write the same bytes (`optimize`, `platforms`).
2. **Safe on hostile input.** Nino reads untrusted bytes: nothing may crash, read outside the input, allocate or take
   time out of proportion to it, or recurse without a bound (`audit-security`), in every runtime.
3. **The bytes are the contract.** .NET, Go, Rust, TypeScript and the generated code write identical bytes; a change
   to them is a wire-format change with everything `wire-format` lists.
4. **DRY and decoupled.** One implementation, one way per job, one source of truth per fact; dependencies point one
   way through public seams; standard practice over a new mechanism. The standard is stated in `audit-code`.
5. **Proven.** Tests for behavior, the machine code for hot paths, runner numbers for speed (`benchmark`).

## Rules

- **Numbers**: performance claims come only from GitHub runners (`report.yml` for releases, the A/B workflows while
  developing). Never publish quick, local or editor numbers. Within 5 % is on par; the docs never call Nino
  "slower". v3 means 3.3.13.
- **CI stays green** on `main` and on the test branch: run the checks for what you touch before every push, never push
  an experiment that fails on purpose, batch test-branch pushes (`verify`, `audit-ci`).
- **Commits**: Conventional Commits, `type(scope): summary` and a body that says why (types `feat`, `fix`, `perf`,
  `refactor`, `docs`, `test`, `ci`, `build`, `chore`; scope = area). Author:
  `git -c "user.name=JasonXuDeveloper - 傑" -c user.email=jason@xgamedev.net -c commit.gpgsign=false commit`. The
  message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` only: no session link, no model id.
- **Release notes are trailers.** `.github/scripts/release_notes.py` groups commits by type and takes highlights
  from trailers in the last paragraph, next to `Co-Authored-By`: `Wire-Format:` (bytes that change, for which
  types), `Added:` (API, attribute, behavior), `Performance:` (what, which types, how much, runner numbers),
  `Fixed:` (a user-visible bug). One or two sentences of Markdown for users; `Closes #N` in the body above them. Tests,
  CI, docs and refactors get none. The docs site's changelog is written from the same trailers (`audit-docs`).
- **Landing**: `main` moves only by fast-forward
  (`git fetch -q origin main && git merge-base --is-ancestor origin/main HEAD && git push -q origin HEAD:refs/heads/main`);
  the test branch only by merge. No force push, no pull request unless the owner asks, never trigger a release.
- **Shell**: never bare `git stash`, `pkill -f` or `pgrep -f`; heavy commands (builds, tests, benchmarks, cargo) run
  under `flock -o /tmp/nino-heavy.lock` when agents share the machine; scratch files stay out of the repository.
- **Secrets** go only into GitHub secrets, never into chat, files or logs.
- **The owner talks in Chinese**: answer in Chinese; everything committed stays English (docs: English and Chinese).
