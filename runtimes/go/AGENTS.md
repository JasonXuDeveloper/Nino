# Go runtime: file map

> Read when: reading or changing the Go runtime (runtimes/go, package nino), its string kernels, struct tags, sample codecs or Go benchmark.

Module `github.com/JasonXuDeveloper/Nino/runtimes/go/v4` (Go 1.22, no dependencies): the Reader and Writer
generated Go code calls, struct tags as a reflection-based alternative, and the corpus tests; README.md documents
the API and its guarantees. nino-gen's Go target (`runtimes/csharp/src/Nino.Codegen`) writes code in the style of
`internal/sample`. `audit-runtimes` audits it, `audit-security` its read paths.

## Go runtime

`runtimes/go` (package `nino`, see its README.md) reads and writes the wire format for Go; `internal/sample` holds the
corpus's types with codecs in the style a generator would write. Both performance and safety on untrusted input are
requirements:
- Never panic on any input, and never rely on `recover`: check every bound, and keep errors sticky (after a failure
  the reader returns zeros, empty slices and null, so every loop ends). Check a length against the bytes left
  before allocating, with .NET's caps (`SliceCap`, `capacity`: one budget for the whole read, `audit-security`);
  grow, never presize, what the data only claims.
- Count depth exactly as .NET does (`ReadClass`, `WriteClass`, regions and sections): the bytes must match, and
  the stack must stay bounded however deep the data. A polymorphic slot accepts only the ids of the types it allows.
- Hot paths: no reflection, no boxing into `any` outside polymorphic slots; a run of fixed-size members is one
  `Take`/`Extend` and `binary.LittleEndian` at constant offsets; blocks of primitives are one copy (guarded for
  big-endian hosts). Keep rare paths (`Fail`, growth, deferral) in `//go:noinline` functions. Check
  `go build -gcflags=-d=ssa/check_bce/debug=1` and `-gcflags=-m` on what you change, and keep writing a value free
  of allocations (`bench`, `-benchmem`). A collection of fixed-size elements takes a block helper
  (`ReadPrimitives`, `ReadPrimitiveEntries`, `ReadPrimitiveMap`), never the generic helpers that take element
  functions: those are an indirect call per element (`(*Reader).I32` is never inlined through a func value) and a
  bounds check per value. Generated fixed-width maps, sequences, sets and grids without a matching bulk copy
  share a cursor loop at constant offsets. Raw sequences still attempt the memory copy through `TryReadRaw` /
  `TryWriteRaw`, then take the same cursor on other hosts. Other generated collection loops also call the
  element's codec directly (nino-gen's `read_loop` / `write_loop`; `optimize-runtimes`, references/dispatch.md).
  `ReadPrimitiveMap` read a 10-pair `map[int32]int32` 31 % faster than `ReadMap` (now unexported), and
  SimpleClass 4-7 % faster on runners (7ac8b46). Walk a block with a cursor (`for len(b) >= wire { ...; b =
  b[wire:] }`): indexing `b[i*wire:]` kept a bounds check per pair. A runner A/B can move code you did not touch by
  layout: the first map round left the untouched tag write 1.5-7.7 % slower on x64 only; make that path faster too
  (it then measured 7-14 % faster) rather than land a loss.
- Checks over a block (ranges of dates and decimals, the bools of raw structs) and UTF-16 copies: what measured
  faster and slower is in the `optimize-runtimes` skill, "Checking blocks in Go"; time them with BenchmarkBlocks and BenchmarkUTF16.
- Struct tags (`tagged.go`, `layout.go`, `marshal.go`) are the one place reflection is allowed: a plan built once
  per type, then walked. Anything the wire format cannot express is a `*TagError` naming the field when the plan
  is built, never a silent default; reads go through the same `Reader` calls as generated code, so the guarantees
  above hold there too. The sample types carry the tags and `NinoLayout` a generator emits (README, "Tags on
  generated structs"); keep them and `internal/sample/tagged_test.go` in step with the hand-written codecs.
  A type decides its own encoding wherever the wire has two for one .NET shape: `nino.NinoNullable[T]` is .NET's
  `NinoNullable<T>`, a `*T` a single `T?` (a slot at its offset as a field of a raw struct) and a
  `nino.NullableSlot[T]` a `T?` as the element of a sequence, with or without a layout (`ninoNullable`, `slot`,
  `stride`, `nullablesIn`); never let a layout's text pick the encoding of a Go type, since a type without a layout
  then has no way to say it (a `[]*T` was the slots of a `T?[]` unless a layout said `seq(nullable(...))`: it is now
  always one single `T?` per element, and a layout of slots over it is a `TagError` naming `nino.NullableSlot`).
- Before committing: `go vet ./...`, `go test -race ./...` with the conformance corpus present, a short run of
  `FuzzReader`, `FuzzDecode`, `FuzzTagged` and `FuzzTaggedDecode`, and the benchmarks back to back against the
  previous commit for a change to a read or write path. The runtime's module has no dependencies; competitors live in the `bench` module.
- The module says Go 1.22 and CI builds and tests it with Go 1.22: no API newer than that outside the `bench` module,
  tests and benchmarks included (`testing.B.Loop` is Go 1.24: loop with `for range b.N`). Check with
  `GOTOOLCHAIN=go1.22.12 go vet ./...` before pushing. CI also tests 386, Arm32 and big-endian s390x: run
  `GOARCH=386 go test ./...` (a constant such as `1<<31` compared with an `int` does not build there, and a test that
  hard-codes a pointer's size as 8 reads past its slice; both reached main in r101) and, with qemu-user,
  `GOARCH=arm GOMAXPROCS=1 go test -exec qemu-arm ./...` (several Ps crash Go 1.27 under qemu: `platforms`) and `GOARCH=s390x go test -exec qemu-s390x ./...`.
